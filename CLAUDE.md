## Build and test facts not in AGENTS.md

- There is no build system. No Makefile, CMake, PlatformIO or test framework. Each `tests/test_*.cpp` is a standalone program with its own `main()` that includes `../src/FieldUnit.h` and uses `assert()`. The `for t in tests/*.cpp` loop in AGENTS.md is the whole test runner; a new test file is picked up by that glob with nothing to register.
- Never compile tests with `-DNDEBUG`: every check is an `assert`, so an optimized build with asserts stripped passes vacuously.
- The full suite (19 programs) compiles and runs in well under a minute on this Mac. `-Wall -Wextra` is not clean today (an unused parameter in `SignalAspectPolicy.h`, a constructor-order warning in `InterlockingPlant.h`), so do not treat a warning-free build as a gate, but do not add new warnings.
- Sketch tests (`test_corporal_sketch.cpp`, `test_christopher_sketch.cpp`, `test_universal_sketch.cpp`) do `#undef ARDUINO` and then `#include` the `.ino`. A sketch is therefore a header for test purposes: keep `configurePlant()` and `executeCycle()` native, and keep anything that needs `Wire`, `Serial`, `LittleFS` or sibling Arduino libraries behind `#ifdef ARDUINO`.
- `arduino-cli` 1.5.1 is installed via Homebrew with cores `esp32:esp32` 3.3.12 and `arduino:avr` 1.8.8. `--libraries ..` is required because sketches depend on sibling libraries in the parent `libraries/` folder (`I2Cexpander`; the desk also needs `PubSubClient`, `Adafruit_GFX`, `Adafruit_SSD1306`). The `CP_Corporal` ESP32 build takes about 15 s once the core is cached.
- The staleness default for line inputs and track circuits is `DEFAULT_STALENESS_TIMEOUT_MS` in `src/types.h`, set at compile time with `-DFIELDUNIT_DEFAULT_STALENESS_TIMEOUT_MS=<ms>` and overridden per interlocking with `setDefaultStalenessTimeout()` / JSON `defaultStalenessTimeoutMs`, or per fact (FieldUnit ADR 0009).
- `tools/test_ctc_desk.py` needs `paho-mqtt`, which is not installed in the system Python. Install it in a venv before running the tool.
- `.gitignore` ignores `*.pdf`; the PDFs under `docs/` are tracked exceptions that predate the rule. Do not add new PDFs expecting them to be committed.

## Cross-file invariants

These are the things that take reading several headers to discover and that break silently when violated.

- **Appliance index is declaration order.** `addSwitch`, `addTrackCircuit`, `addSignalControl`, `addSignalMast` assign `index()` in call order. `ControlTransaction` and `IndicationVector` are fixed arrays indexed by that number (`MAX_APPLIANCES` = 16 per kind; `MAX_ROUTES` = 32; `MAX_ROUTE_SWITCHES` = 8; names are at most `MAX_APPLIANCE_NAME_LEN` = 16). Reordering `addX` calls in a sketch reorders the wire schema and the lever harvest without any compile error.
- **The wire schema order must match on both ends.** On the field side the order of the `decodeControls({...})` and `encodeIndications({...})` entry lists is the token order on the wire. On the office side `cTcMachine` compiles each station into the canonical order Switches → Tracks → Signals → Maintainers (`cTcMachine.h`, `CtcStation`). `AarTextCodec::decodeIndications` rejects a message with a missing, extra or out-of-order token as "out of version sync" rather than applying it partially. The `STATIONS` strings in `tools/test_ctc_desk.py` are a third copy of the same order. Change one, change all three.
- **The field-unit cycle has one shape.** Every field sketch's `executeCycle()` is: receive on a `CodeLine` → `codec.decodeControls` → `cp.applyControlTransaction` → `cp.tick(nowMs)` → `cp.exportIndicationVector` → `codec.encodeIndications` → transmit. Tests drive it with `MockCodeLine::injectControlText` and read `outboundText()`. Hardware I/O has two paths: the example sketches call per-appliance drivers (`TrackCircuitDriver`, `SwitchDriver`, `SignalMastDriver`) around `executeCycle()` from `loop()`, while the `DriverPolicy` path (`setDefaultDriverPolicy`, `overrideDriver`, `mockSwitch`) runs inside `tick()` and is today exercised only by `tests/test_driver_policy.cpp`. ADR 0004 (proposed) is where the driver seam is being redesigned; check it before extending either path.
- **`FieldUnit.h` is the only header to include.** Several `InterlockingPlant` methods are defined out of line in other headers: `serialize`/`deserialize` in `PlantSerializer.h`, and `sampleInputs`/`driveOutputs`/`overrideDriver`/`mockSwitch` in `drivers/DriverPolicy.h`. The name-taking configuration calls of `Route`, `AutomaticSignal` and `ControlPointLine` are defined at the bottom of `InterlockingPlant.h`. Including `InterlockingPlant.h` alone links only if nothing calls the first two sets. The leaf buses `drivers/CmriIOBus.h` and `drivers/I2CexpanderIOBus.h` are deliberately left out of the umbrella because they pull in Arduino-only dependencies; sketches include them under `#ifdef ARDUINO`.
- **JSON and the fluent API are the same plant.** `PlantSerializer` keys mirror the `cp.` calls one to one: `trackCircuits`, `switches` (with optional `os`), `derails`, `crossovers`, `signalControls`, `signalMasts` (`type`, `aspectPolicy`), `lineInputs`, `automaticSignals` (`governs`, `approach`, `reads`, `opposing`; read in two passes so file order does not matter), `controlPointLines` (`home`, `governs`, `block`, `leaving`, `tumbleDown`, `traffic`, `trafficRelease`), `detectorLocks`, `routes` (`governedBy`, `displays`, `aligns`, `clears`, `home`, `proceed`, `entrance`, `approaching`). An automatic signal owns its mast and its route; the serializer writes them under `automaticSignals` only, and `isAutomaticMast()` / `Route::isAutomatic()` are how it skips them elsewhere. `examples/CP_Corporal/CP_Corporal.json` and `CP_Corporal.ino` describe the same plant; keep them in step when you change either. Adding an aspect policy or a `MastType` means adding it to the name tables at the top of `PlantSerializer.h`, or JSON silently falls back to `defaultRoute` / `ONE_HEAD`.
- **Names bind at the call, and a mast is an output.** Every name-taking configuration call (`clears`, `home`, `proceed`, `governs`, `reads`, `opposing`, `leaving`) resolves through `findFact()` / `findSignalMast()` when it runs and keeps a pointer, so add every track circuit, line input, automatic signal and control point line before a binding names it (the serializer's two-pass read exists for this). What an unresolved name does, and what may be an operand, are decisions: see the ADR index.
- **No allocation after `setup()`** (FieldUnit ADR 0007 D4). Today every container is a fixed array sized by the constants above; the one startup allocation is the Strategy B codec buffers in `AarTextCodec::preallocateBuffers()`, called once from `cTcMachine::begin()`, which is why `AarTextCodec` is move-only. `std::string` and `std::vector` reallocate, so keep them out of `src/`. Tests may use them.
- **Everything lives in `namespace FieldUnit`.** `CtcMachine` and `OfficeUnit` are aliases of `cTcMachine`; `InterlockingPlant` was formerly `ControlPoint`, and the variable is still conventionally named `cp`.

## Documentation workflow

- `docs/GLOSSARY.md` is the shared source of truth for this repo and FieldUnit-Subdivision. Most recent commits touch only the glossary and ADRs, on `docs/<topic>` branches merged to `main` by pull request on `plocher/FieldUnit`. Glossary entries carry a scope tag (`[Prototype]`, `[FieldUnit]`, `[Both]`, `[US&S 506 code line]`) and mark unsupported claims "(unverified)"; follow that form.
- Design decisions live in `docs/adr/`. `docs/adr/README.md` is the index from code to decision: read the ADRs that name the file you are changing, and update the index in the same commit as a new or revised ADR. Cite every ADR with its repository name; the two repositories' sequences overlap from 0007 on.
- **Order of authority** (owner, 2026-11-02): the ranked list is stated once, in `FieldUnit-Subdivision/AGENTS.md` under "Order of authority", and its first two ranks in the header of FieldUnit ADR 0007. Where `src/` differs from the relay model, the code has a defect: file it, never rewrite the principle. Any claim about what `src/` does needs a file and line citation or an `(unverified)` mark; cite only sources that were opened.
- `docs/CHANGELOG.md` is organized under `## [Unreleased]` with `### Changed`, `### Fixed`, `### Added`, newest entry first within each. Code changes get an entry; documentation-only changes do not need a test run.
